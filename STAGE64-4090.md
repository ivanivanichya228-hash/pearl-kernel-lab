# Revision 0.3.0: deeper operand stages

## What changed

The rejected compact128 case remains available for regression correctness only. The baseline
256 / stage32 is retained. The new candidate is 256 / stage64 with a large 128x320 tile,
compared with baseline 128x384. A 128x384 stage64 double buffer would need too much shared
memory for proof8 on RTX4090. The 320-wide tile keeps both formats within the budget.

- Two 32-wide MMA steps per prefetched stage; cp.async wait/barrier once per 64 K.
- For K4096: 64 loop-end barriers rather than 128, plus the initial barrier for each variant.
- Shared stride80 maintains 16-byte cp.async alignment and distinct banks per packed-word warp load.
- Checkpoints stay after EACH 32-wide step: rank32 still produces two checkpoints per full stage.
- For partial final K stages, out-of-bounds 16-byte vectors are zero-filled; unused MMA steps skipped.
- Existing shared transcript, warp XOR and rotation semantics stay intact.
- Reported shared memory now distinguishes each actual variant (fix for compact128 metadata).
- Both thread count and stage_k appear in JSON results. Candidate256/stage64 is the default.

Compile-only evidence, CUDA13.0.88, SM86/89, debug and non-debug:
224 registers/thread, zero stack and spills. Shared: 81,920 bytes proof16; 92,160 proof8.
Original stage32 baseline has 238 registers/thread for proof16. See COMPILE-0.3.0.json.

CPU model passed signed inputs, rank32/128, proof8/16, edge M/N tiles, partial K stage,
17 checkpoints including rollover, unique vector/cell/proof ownership and packed-load banks.
This does not establish CUDA correctness or faster mining. No GPU work was run here.

Tradeoffs: nominal operand bytes/output rise 5% (ignoring inter-CTA reuse), unlike compact128's
125% increase. The original benchmark shape needs 320 CTAs rather than 256; N padding adds
4.17% extra matrix area. Increased shared memory can reduce available L1. Two-step unrolling
and compiler scheduling can also hurt speed. Only an equal-settings measurement can decide.
No numerical speedup/energy estimate is claimed. This is not a full Pearl miner/proof pipeline.

PL, clocks, offset, memory, fans, driver, pool, wallet, desired/profile/autostart. No 3060/Hive tests.
