# Готовая тестовая сборка Mint RTX 4090

## Задание домашнему Codex

Подготовь установку архива `pearl-test-0.1.0-linux-x86_64.tar.gz` на Mint RTX4090
room-room@192.168.1.98. В этом этапе НЕ останавливай SRBMiner, не запускай GPU-тест
и не меняй автозапуск, драйверы, разгон, PL310 Вт, память405 или вентиляторы55%.
3060 и Hive не затрагивай.

1. Найди скачанный архив в домашней папке/Загрузках. SHA256 должен быть
   `28fdca1aaac1e597a5cd8cfad0d39db35120be1ecfa4857fed0e80af5662f157`.
   Проверь безопасные относительные пути архива; распакуй в НОВЫЙ каталог рига.
   Не перезаписывай рабочие каталоги майнеров или панели.
2. Прочитай README_RU.md и integration/CONTROLLER.md. Выполни `./pearl-test version`
   и `./pearl-test verify`. Это проверяет комплектность, загрузку бинарников и
   nvidia-smi; CUDA-вычислений и подключения к пулу нет. Готовые бинарники включены:
   не устанавливай Toolkit/Rust/NumPy, не пересобирай и не обновляй драйвер.
   При несовместимости остановись с точной причиной.
3. Импортируй предыдущий приватный конфиг теста командой
   `./pearl-test configure --import-config /абсолютный/путь/к/config.json`.
   Сохрани прежние pool host/port/wallet/worker; секреты не печатай и не публикуй.
   Профиль берётся из комплектного share/profile.json. Если предыдущий конфиг
   отсутствует, сообщи об этом; не подставляй выдуманный кошелёк или другой пул.
4. Найди существующий ПРОВЕРЕННЫЙ внешний контроллер с pidfd, watchdog590s,
   ограничением cgroup555s и строгим восстановлением исходного SRBMiner.
   Прочитай его код и интегрируй входной файл `pearl-test run` вместо прежнего
   GPU-клиента. Существующий порядок остановки/возврата и проверки не переписывай.
   Issuer из integration/issue_session.py допускается импортировать root только
   после проверки и установки неизменяемой обычным пользователем копии в закрытый
   root-каталог. Не запускай root-код из пользовательского каталога и не добавляй
   универсальное NOPASSWD/sudo-разрешение.
5. Контроллер выдаёт receipt ТОЛЬКО в реальном будущем тесте после включения watchdog,
   подтверждения всех потоков T, простоя GPU и отсутствия других вычислений.
   Сейчас не выдавай receipt и не вызывай остановку. Подготовь точный будущий запуск
   с root-receipt, привязкой к cgroup/таймеру, UID/GID1000, всеми capabilities=0,
   NoNewPrivileges=yes, private tmpfs и длительностью420s. Общая пауза <=600s.
   Внешний контроллер обязан завершить/собрать ВСЮ cgroup до SIGCONT и подтвердить
   тот же PID/start ticks, свежий хешрейт, задания/принятую шару и исходные настройки.

Результат этапа: каталог установленной сборки, версия, совпадение SHA, результат
verify, приватный конфиг без раскрытия значений и точная команда существующего
контроллера для будущего теста. Явно укажи, что майнинг не прерывался. Если root-доступ
не настроен, подготовь конкретную root-установку только адаптера, без запуска теста.

## Статус и границы

Ядро triple384 уже использовалось в 420-секундном тесте с одной принятой шарой.
Комплектный CUDA13-бинарник собран отдельно и ещё не проверен на GPU; это следующий
аппаратный этап. Ускорение относительно SRBMiner не доказано. Комиссия разработчика0%.
Скорость выводится в свежих группах/с, без подмены единиц на TH/s SRBMiner.

## Повторная сборка пакета разработчиком

Из корня репозитория, с уже собранными доверенными бинарниками:

```bash
python3 release/build_test_release.py --out /абсолютный/НОВЫЙ/каталог \
  --engine /путь/к/pearl-bench --oracle /путь/к/pearl-protocol-oracle
```

Сборщик проверяет закреплённый SHA oracle, вычисляет требования ELF, включает
лицензии и проверяет загрузку без GPU. Конфиги с кошельками в архив не включаются.
