# Pearl Test Miner 0.1.0-test

Тестовая сборка для твоего рига Mint с RTX 4090. Вычислительное ядро — triple384 из
коммита ea171542e94331dfa576d57f60f1b54f5be5797e. У него уже пройден 420-секундный
майнинг и подтверждена принятая пулом шара. Этот упакованный CUDA13-бинарник собран
отдельно и ещё не проверен на GPU. Скорость выше SRBMiner не доказана.

Комиссия разработчика — 0%. Используется только заданный кошелёк и заданный пул.
Комиссия самого пула определяется пулом. Проверен plain JSON-протокол LuckyPool;
совместимость с другими протоколами пулов не заявлена.

## Что внутри

- `pearl-test` — единая команда: настройка, проверка, запуск ограниченного теста.
- `bin/pearl-engine` — готовый CUDA-бинарник с triple384.
- `bin/pearl-protocol-oracle` — готовое создание и проверка доказательств.
- `lib/` — клиент пула, очередь и статистика; только стандартная библиотека Python.
- `share/profile.json` — прежний полный профиль Pearl, не уменьшенный benchmark.
- `config.example.json` — пустой образец без кошелька, ключей или токенов.

Для запуска не нужны компилятор, CUDA Toolkit, Rust, NumPy или интернет-загрузка модулей.
Нужны Linux Mint x86_64, Python >=3.10, NVIDIA driver >=580 и glibc >=2.38.
Точные требования записаны в manifest.json. В сборке закреплена именно тестируемая
Mint4090 GPU-14cc341d-41f4-a977-1a1d-12785f4079da и ожидается PL310 Вт; программа не
применяет разгон, лимиты мощности или скорость вентиляторов.

## Подготовка

Распаковать в НОВУЮ папку, не поверх SRBMiner или панели:

    tar -xzf pearl-test-0.1.0-linux-x86_64.tar.gz
    cd pearl-test-0.1.0-linux-x86_64
    ./pearl-test version
    ./pearl-test verify

`verify` проверяет файлы, загрузку исполняемых файлов без CUDA-работы и карту/PL/драйвер.
Соединение с пулом и GPU-ядра не запускаются. Для проверки файлов на другом Linux:

    ./pearl-test verify --offline

Перенести прежние пул, порт, кошелёк и worker из приватного конфига теста:

    ./pearl-test configure --import-config /путь/к/прежнему/приватному/config.json

Или ввести эти поля локально:

    ./pearl-test configure

Создаётся НОВЫЙ config.json с правами0600. Существующий файл не перезаписывается.
Кошелёк не выводится в журнал. Конфиг не публикуется в GitHub. Импорт сохраняет значения
host/port/wallet/worker, а профиль заменяет только на комплектный тот же полный профиль.

## Безопасный тест и возврат SRBMiner

Запускать `run` должен уже проверенный внешний root-контроллер с pidfd, независимым
watchdog и отдельной systemd-cgroup. Он останавливает исходный SRBMiner, запускает этот
пакет обычным пользователем и восстанавливает прежний процесс после завершения всей
экспериментальной cgroup. Сам пакет root не требует, майнер не останавливает и GPU-настройки
не меняет. Не останавливай SRBMiner вручную ради обхода контроллера.

Контроллеру передаётся одна команда:

    ./pearl-test run --config config.json --session /run/pearl-test-sessions/ID/session.json \
      --state /путь/к/НОВОМУ/приватному/запуску --ram-dir /проверенный/private/tmpfs --duration 420

Здесь `session.json` выпускает контроллер, не пользователь. Пакет проверяет root-владельца,
защищённые каталоги, срок, принадлежность текущего процесса нужной cgroup и активный watchdog.
Без этого файла запуск блокируется до вычислений. Продолжительность 1–420 секунд,
общая пауза задаётся контроллером и не может превышать600 секунд. Настройку интеграции
выполнит домашний Codex по TEST-RELEASE.md из репозитория; ручные PID/сигналы не требуются.

Статистика показывает проверяемую скорость свежих групп/с, принятые/отклонённые/неизвестные
шары. Эти единицы пока не равны автоматически TH/s SRBMiner. Хранятся структурированный
журнал events.jsonl, performance.json и доказательства/ответы пула в приватной папке запуска.
Ctrl+C завершает клиент и его backend; внешний контроллер проверяет завершение всей cgroup
и возврат исходного SRBMiner. Ошибка/отказ/неизвестный ответ на шару завершает тест без
автоматического переподключения или замены ядра.

Это тестовая версия, а не установка нового производственного майнера или автозапуска.
