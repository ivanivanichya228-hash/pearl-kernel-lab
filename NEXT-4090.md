# Revision 0.2.0: compact kernel

## Implementation and evidence

Baseline 256 and legacy 512 kernels keep their original 128x384 tiles and shared transcript.
The new variant selects 128 threads, a 64x128 tile, 2x2 warps, and a 32x64 warp tile.
Accumulator elements/thread decrease from 192 (baseline) to 64. Each lane 0..15 owns one
rolling transcript slot for each of its warp's proofs. Other lanes keep participating in MMA
and warp XOR. No shared transcript initialization, load/store or final redistribution is needed.
Double-buffered cp.async and the end-of-step barrier are retained: removing that barrier
would allow the next writer to race with current readers.

Dynamic shared memory: 18,432 bytes instead of 61,440 (proof16 baseline).
CUDA 13.0.88 compilation for SM86 and SM89: 116 registers for proof16, 119 for proof8;
zero stack/spill bytes, including debug specializations. Baseline proof16 remains 238 registers.
Resources suggest more resident blocks; obtain actual active_blocks_per_SM from the harness.
This is a resource improvement, not a measured hashrate improvement. Smaller tiles increase
input traffic per matrix output and may lose performance; the comparison must decide.

CPU checks: six independent fixtures, PTX ownership model, compact ownership and transcript
model (signed extremes, proof8/16, edge tiles, 17 checkpoints including slot rotation), and PL guard.
GPU correctness, compute-sanitizer, full Pearl proof and speed gain remain unverified.
The bundled bin executable is legacy. Build the new source before use; guard refuses stale builds.
